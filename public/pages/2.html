Scope

Der hvor et variabel er synligt
Scope defineres af hvor variablen ligger

  • var: function scope

  • Variablen lever i hele funktionen. Kan kaldes når som helst

  • leaker ud af block scopes. ({})

  • let, const: block scope

  • variablen lever kun i block scope.

  • mest brugt, da den ikke leaker ud (eller ind (shadowing)) af block scopes. ({})


Hoisting

TDZ: Temporal Dead Zone mellem det hoistede variabel og til den initializeres.

  • var: hoisted til toppen af funktion

  • variablen bliver initializeret, men retuneres med undefined inden den bliver defineret.

  • let, const: hoisted til toppen af block scope

  • variablerne er ikke initzializeret og kan ikke bruges før let fo = bar (TDZ).

  • bruges den før kaster den refrenceError.

brug altid const. Ellers brug let hvis værdien skal ændres under vej.


Funktioner

  • deklaration:

  • function add(a, b) { return a + b };

  • funktionen er deklereret. Har et navn og bliver hoisted.

  • expression:

  • anonym funktion: const add = function (a, b) {return a + b };

  • navngivet funktion: const add = function plus(a, b) { return a + b };

  • arrow:

  • const add = (a, b) => a + b;

  • first-class citizen:

  • Funktioner er værdier. Kan tildeles til variabler, gives som argument og retuneres.

  • implicit return

  • arrow funktion uden block scope ({}) retunere hvad end der er på den anden side af =>

  • arrow funktion med block scope skal retuneres med return.


Callback function

Node er single thread. Callbacks tillader at en funktion kan blive kaldt senere uden at blokere tråden.

Navngivet function

function playingGuitarAction(name) { return name + " likes to play guitar"; };

genericActionPerformer("Elias", playingGuitarAction);

Arrow med block body

genericActionPerformer("Magnus", (name) => { return name + " likes to watch movies"; });

One-liner arrow (implicit return)

genericActionPerformer("Jacob", (name) => name + " likes to sail");

i express er Route handler en callback funktion.

app.get("/", (req, res) => { ... })

Client-Server model

Client requester resourcer

Server lytter, bearbejder requests og svare

request -> response over HTTP (stateless)

Request har method, URL, headers, og valgfrit en body

Response gar status kode, headers, body.

Port der hvor serveren lever

Localhost lokale ip adresse på computer 127.0.0.1

HTTP Status koder

  • 1xx = info

  • 2xx = success

  • 200 ok

  • 201 created

  • 204 no content

  • 3xx = redirection

  • 301 nyt domæne

  • 302 videre på samme domæne

  • 4xx = client side error

  • 400 bad request

  • 404 not found

  • 5xx = server side error

  • 500 internal server error

Path/Query parameter

GET har ingen body, men kan request data igennem URL

  • Path parameter

  • /beers/lager/6

  • /beers/:beerType/:amount

  • sender beerType og amount videre i GET Methoden

  • Query parameter

  • /bars/forgottenItems?userId=1&employee=true

  • sender userId og employee videre i GET methoden

alt i URL er en string. Konvertere tal med Number()
